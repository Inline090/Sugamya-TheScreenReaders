## Why not more MCP servers?

We compared needed capabilities with existing tools: Git/repository CLI already works; fetch/search supplies primary standards research; axe/Playwright supplies accessibility testing; npm audit/ESLint/Gitleaks supply security checks. Additional filesystem/Git/security MCP servers would duplicate access and enlarge the credential/attack surface. Only the official Playwright MCP adds an exercised protocol/browser capability; it was installed and used, not just linked.

## Actual Taste workflow and critique

- Inventory: authorized origin, task baseline, criterion decisions, four operations, three semantic holds, exact version, visitor evidence and rollback, single operator/approver deployment.
- Screen's question: **“Can this reviewed version safely reach visitors, and what proves it?”** Signature element is the real seven-step change-control strip, not a fictional analytics chart.
- Dealt achromatic ledger style with actual Geist font assets served locally; one data hue; label/value denominators from live API. No external font CDN dependency, fake KPI trend, decorative motion or visitor toolbar.
- First visual inspection identified mobile sign-out invisibility, 12px dense labels and split disclosure-row alignment. Fixed all three, reran real browser tests/official inspector and looked at screenshots.
- Final screenshots: readable operational hierarchy, no horizontal viewport overflow at three widths, 3px visible keyboard focus, reduced motion, zero axe findings in the tested console state. This is not a full manual accessibility audit.
- The inspection harness temporarily exposes the real authenticated UI **only on localhost**, with server-side operator capability injection. It is development-only and shuts down after the official inspector exits. No fake records/API responses are supplied. Separate real-login browser tests exercise production authentication.
